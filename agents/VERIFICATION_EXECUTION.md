# Безопасное выполнение проверок

Обычное чтение файлов, Git status/diff и AST-анализ не запускают приложение.
Перед импортом, тестом, запуском или сборкой проверь фактические побочные действия.

`screen_recorder.shared` при импорте выбирает writable `DATA_DIR` и `LOGS_DIR`,
создаёт папки и проверочный `.write_test`. `APP_DIR` определяется расположением
исходников, а не текущей папкой shell. Поэтому смена cwd или TEMP не изолирует
импорт из рабочей копии программы.

Для автоматических проверок:

1. Создай новую отдельную папку под `work/` внутри этого проекта.
2. До копирования зафиксируй соответствие исходник → копия. Проверь отсутствие
   совпадающих целей и существующих файлов; копируй только Python-исходники
   `screen_recorder/` и корневые Python launchers/проверки с сохранением структуры.
   Не переноси настройки, записи, логи и чужие тестовые папки.
3. Убедись, что новая папка доступна для записи. Запускай проверки из неё;
   проверь, что `APP_DIR`, `DATA_DIR`, `SETTINGS_PATH`, `LOGS_DIR` и
   `TEMP_RECORDINGS_DIR` разрешаются внутри копии. Если fallback выбрал другую
   папку, останови проверку и исправь изоляцию.
4. Используй тесты с `object.__new__`/подставными объектами без конструктора
   приложения. Реальные FFmpeg-проверки используют только искусственные входы
   и свои временные результаты. Они не записывают экран, микрофон и системный звук.
5. До утверждения результата сравни хеши проверенных исходников с рабочими.
   После изменения кода обнови соответствующие копии и повтори затронутые проверки.

Конструктор приложения запускает устройства, горячие клавиши и служебную очистку;
его вызов не является безвредной проверкой импорта. GUI, живые устройства,
ddagrab/NVENC, плавность, синхронизация и EXE проверяются отдельно.

Команды и ручной сценарий находятся в
[`Docs/07_DEVELOPMENT_AND_TESTING.md`](../Docs/07_DEVELOPMENT_AND_TESTING.md).
