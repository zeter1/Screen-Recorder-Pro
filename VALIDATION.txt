SCREEN RECORDER PRO — ОТЧЁТ ПРОВЕРКИ ОБНОВЛЁННОЙ ВЕРСИИ
Дата: 2026-08-11
Сборка: 2026-08-11-screenshot-selector-logs-v11
Схема логов: screen_recorder_diagnostics_v11

Что изменено в v11:
1. Устранена мёртвая зона выбора скриншота: верхняя подсказка теперь рисуется внутри Canvas и не перехватывает мышь.
2. Добавлена точная цепочка JSONL-событий выбора области: открытие, нажатие мыши, результат, координаты, размер, время и причина отмены.
3. Слишком маленькая область теперь получает статус too_small и понятное сообщение вместо безымянного screenshot_cancelled.
4. Повторное нажатие во время снимка и отсутствие Pillow записываются отдельными событиями с причиной.
5. Обычные и ошибочные логи хранятся 120 дней.
6. Автоочистка удаляет только распознанные логи Screen Recorder Pro и сохраняет посторонние пользовательские файлы.
7. Стабильный контур ddagrab/NVENC/CFR/аудио не менялся.

Сохранённые свойства v10:
1. Надёжность Print Screen/глобальных хоткеев после автозапуска Windows.
   - регистрация выполняется сразу;
   - при запуске из автозагрузки повторная регистрация идёт через 3, 10 и 30 секунд;
   - через 32 секунды пишется startup_hotkey_health_summary;
   - отдельно пишется hotkey_callback_received, поэтому видно границу Windows-hook -> очередь программы;
   - отложенные задания отменяются при выходе.

2. Общий diagnostic исправлен и уменьшен.
   - файл с первой строки является валидным JSONL;
   - устранена ошибка, из-за которой текстовый header мог повторяться десятки раз;
   - diagnostic_latest.txt — только маленький указатель;
   - при достижении лимита сохраняются начало и свежий хвост, после чего лог продолжает писаться.

3. Логи записи оптимизированы для ChatGPT и веса.
   - 00 — короткая AI-карта сессии, а не копия больших отчётов;
   - 01/07/08 используют адаптивное семплирование и сохраняют аномалии подробнее;
   - 02 не дублирует одинаковые FFmpeg-команды и большой ожидаемый device-probe stderr;
   - 14 хранит полный timing, а 01/general diagnostic — только компактную timing-сводку и ссылку;
   - повторная вставка 03 в общий diagnostic заменена ссылкой на файл;
   - при компактации JSONL сохраняются только целые UTF-8/JSON-строки;
   - лимиты шумных файлов остаются ограниченными, но конец долгой записи больше не теряется.

4. Исходный код больше не копируется в каждую успешную запись.
   - 11_версия_исходников.json содержит список Python-файлов, размеры и SHA-256;
   - 11_исходный_код_только_при_ошибке.py создаётся только при реальной ошибке;
   - snapshot ошибки ограничен 300 КБ.

5. Уменьшены ложные предупреждения анализа плавности.
   - low_visual_update_cadence влияет на статус только если движение есть минимум в 50% переходов окна;
   - в основном статичные окна с коротким движением не считаются доказанной проблемой;
   - большие массивы подробностей в 09/10/06 ограничены и не копируются в несколько файлов без необходимости.

6. Тяжёлый визуальный анализ больше не задерживает готовность видео.
   - сначала запись останавливается, файл собирается и проверяется;
   - затем 09/10/финальный 06 создаются фоновым пост-анализом;
   - при старте новой записи или выходе пост-анализ отменяется, чтобы не конкурировать с записью.

7. Снижено число фоновых FFmpeg-процессов.
   - аудиоиндикаторы запускаются только когда окно настроек реально открыто;
   - при закрытии настроек meter-FFmpeg останавливаются;
   - перечисление аудиоустройств больше не запускается каждые 15 секунд в трее;
   - настройки обновляют устройства при открытии/ручном обновлении и страховочно раз в 90 секунд, пока окно открыто;
   - во время записи авто-probe не выполняется.

8. Стабильный контур записи НЕ менялся.
   - ddagrab/NVENC/CFR/аудио-пайплайн из стабильной базы не переписывался этой доработкой.

Реально проверить можно только на Windows:
- физический Print Screen после автозапуска;
- начало выделения прямо поверх верхней чёрной подсказки;
- Esc и слишком маленькая область с проверкой точной причины в diagnostic JSONL;
- низкоуровневый keyboard-hook и suppress=True;
- ddagrab/NVENC/WASAPI/Windows Clipboard;
- реальное отсутствие meter-FFmpeg в Диспетчере задач при закрытых настройках;
- субъективную плавность и время завершения реальной записи.

Как проверить на Windows:
1. Выполнить: `python verify_project.py`.
2. Запустить программу и открыть настройки: индикаторы звука должны работать.
3. Закрыть настройки: служебные FFmpeg индикаторов должны завершиться.
4. Сделать запись 2–5 минут и нажать Stop.
5. Видео должно стать доступным после сборки/проверки, а 06/09/10 могут ещё короткое время иметь pending/background status.
6. Начать следующую запись сразу после предыдущей: старый post_save_diagnostics должен отмениться.
7. Проверить размер новой папки «Логи проблем»: 11_версия_исходников.json должен быть маленьким; полного snapshot кода при успешной записи быть не должно.
8. Перезагрузить Windows с включённым автозапуском, не перезапускать программу вручную, через 40–60 секунд нажать Print Screen.
9. При проблеме передать всю папку соответствующей сессии и diagnostic_*.txt. В diagnostic должны быть регистрации 0/3/10/30 секунд, startup_hotkey_health_summary и, после нажатия, hotkey_callback_received.
