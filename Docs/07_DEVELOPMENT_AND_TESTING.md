# 07. Разработка и проверка изменений

## Базовый workflow

### 1. Зафиксировать стабильную точку

Перед крупной задачей:

```powershell
git status
git add .
git commit -m "Стабильная версия перед <задача>"
```

Runtime-папки должны быть исключены `.gitignore`.

### 2. Локализовать изменение

Сначала найди:

```powershell
rg "имя_метода|текст_ошибки" screen_recorder
rg "self\.нужное_поле" screen_recorder
```

Определи основной модуль и связанные вызовы.

### 3. Не смешивать типы работы

Отдельно:

- исправление бага;
- изменение FFmpeg-команды;
- рефакторинг;
- переименование;
- форматирование;
- обновление документации.

Так проще найти регрессию в Git.

### 4. Добавить регрессионную проверку

Для ошибки, которую можно воспроизвести без Windows, добавь проверку в:

```text
verify_project.py
```

или создай тест в:

```text
tests/test_<subsystem>.py
```

Проверка должна падать до исправления и проходить после него.

Пример уже добавленного gate: поиск `@staticmethod`, который обращается к `self` или `cls`.

## Минимальный smoke test

После любой значимой правки:

1. Запуск и появление трея/плавающей кнопки.
2. Открытие и закрытие настроек.
3. Запись 30–60 секунд.
4. Stop и ожидание финализации.
5. Проверка итогового файла.
6. Проверка папки логов.
7. Полный выход и отсутствие висящих процессов.

Для правки скриншотов дополнительно:

- открыть выпадающее меню браузера, список вкладок или панель стикеров;
- нажать горячую клавишу скриншота, не закрывая эту панель;
- убедиться, что панель видна на неподвижном фоне рамки выделения;
- убедиться, что возле курсора появились собственные кнопки `Область`, `Рисовать`, `Стрелка`,
  `Назад` и `Очистить`, а начальным активен режим `Область`;
- выбрать `Рисовать`, провести линию, выбрать `Стрелка`, протянуть стрелку;
- проверить, что под `Рисовать` палитра остаётся открытой после выбора цвета и после линии;
- нарисовать две линии разными цветами, затем выбрать `Стрелка` и поставить стрелки
  разными цветами; убедиться, что у обоих инструментов запоминается собственный цвет;
- выбрать разные размеры карандаша и стрелки, проверить визуальную толщину и поле
  `annotation_sizes` в итоговом событии;
- перетащить основную панель за `✥`, завершить скриншот, перезапустить программу и
  убедиться, что позиция, цвета и размеры восстановились;
- нажать `Область`, выделить фрагмент с пометками и убедиться, что служебная панель
  не попала в готовый снимок;
- выделить её и проверить вставку через `Ctrl+V`;
- проверить события `screenshot_snapshot_*`, `screenshot_annotation_*`,
  `annotation_backend=screenshot_canvas_v3`, итоговые поля `annotation_colors`,
  `annotation_sizes`, `toolbar_position_source`
  и источник `frozen_snapshot_before_selector_focus`.
- при запуске с `--tray` проверить `screenshot_backend=windows_register_hotkey`,
  `native_registered=true` и живой `native_thread_id` после повторов 3/10/30 секунд;
- после полного выхода убедиться, что `native_screenshot_hotkey_stop_result` не оставил живой поток.

## Расширенный тест записи

Для правки плавности:

- непрерывно прокручивать страницу;
- двигать окно по экрану;
- показать секундомер;
- записать минимум 2–5 минут для drift;
- проверить 144 Гц → 72 FPS;
- сравнить длительность секундомера и файла;
- проверить в двух плеерах.

Для правки аудио:

- системный звук с паузами тишины;
- микрофон;
- оба источника вместе;
- pause/resume;
- проверка первых и последних слов;
- stereo channels.

## Проверка сгенерированной команды без записи

При изменении `capture_commands.py` создай объект минимально или вызови метод на объекте-заглушке, чтобы проверить строку фильтра и команду.

Обязательные утверждения для стабильного ddagrab+NVENC:

```python
assert "RTCTIME-RTCSTART" in video_filter
assert video_filter.count("fps=") == 1
assert "setpts=N*" not in video_filter
assert "hwdownload" not in video_filter
```

Также проверь:

```python
assert app.get_ddagrab_poll_fps(72) == 144  # при refresh 144
```

## Работа с версиями

### Границы сегментов и сохранения

`python verify_recording_boundaries.py` проверяет управляемую задержку старого
progress-reader после перехода к новому сегменту/сессии и после фиксации длительности,
штатный финальный progress, а также отказ публикации при сбое/пустом ответе ffprobe
или отсутствующем отчёте. Процессы и GUI подменены; исходники запускаются в отдельной
копии по правилам изоляции ниже.

`python verify_save_safety.py` дополнительно создаёт настоящим FFmpeg две части:
первую без аудио, вторую с аудио. Обычная склейка должна остановиться до создания
готового видео; исходные файлы должны остаться побайтово неизменными. Штатные случаи
с одинаковым набором потоков проверяются по кадрам, звуку и границам дорожек.

Ручная проверка: записать 30–60 секунд с системным звуком, дважды поставить паузу
и продолжить, сохранить, затем сразу начать следующую запись. Проверить отсутствие
скачков таймера/ложных перезапусков, наличие звука до и после пауз. Автотесты не
подтверждают живую работу ddagrab/NVENC, устройств и GUI.

### Восстановление настроек и выход при ошибке запуска

`python verify_settings_recovery.py` использует только временные JSON-файлы и
перенаправленный AppData: повреждённая громкость, диапазон 0–200%, восстановление
из backup, отклонение старого JSON неправильного типа, миграция и сохранность
исправной резервной копии при очередном сохранении.

`python verify_recording_publication.py` также проверяет выход во время отсчёта,
ранний отказ запуска и ошибку FFmpeg после запроса выхода. Callback выхода должен
планироваться один раз после снятия `is_starting`; обычная ошибка без выхода
оставляет программу доступной. GUI/процессы в этих сценариях подменены.

Ручная проверка: во время старта выбрать «Выход». При ошибке запуска программа
должна закрыться, а при обычном запуске — сначала безопасно завершить запись.

### Преобразование системного звука

`python verify_loopback_conversion.py` проверяет искусственные PCM16/24/32 и float32,
mono/stereo, отдельные каналы 5.1/7.1, громкость, ограничение амплитуды и число кадров
для NumPy и резервного пути. Нужен установленный NumPy для сравнения обоих путей.
Неизвестные форматы и повреждённые пакеты должны давать ошибку. Устройства не открываются.

Ручная проверка: на выбранном Windows-устройстве записать речь/системный звук,
поставить паузу, продолжить, остановить. Для 5.1/7.1 дополнительно проверить звук
из центрального и окружающих каналов. Живая запись и синхронизация на устройстве
не считаются подтверждёнными этими синтетическими тестами.

### Пауза во время запуска

`python verify_recording_publication.py` включает переход обратный отсчёт → попытка
паузы → запуск → остановка. Проверяется, что сохранение получает неприостановленную
запись и зарегистрированный процесс; отдельно проверяются обычная пауза/продолжение
и блокировка кнопки при запуске. Потоки/виджеты здесь подменены.

Ручная проверка: во время отсчёта открыть плавающую панель — пауза недоступна.
После старта поставить запись на паузу, продолжить и остановить; проверить итоговое
видео и завершение процесса записи. Этот сценарий пока не подтверждён живым GUI.

### Проверки сохранности экспорта и обязательного звука

`python verify_important_fixes.py` проверяет на искусственных файлах ошибки и тайм-аут
экспорта, сохранность прежнего результата при совпадении имени, отказ публикации
при пропаже зарегистрированного WAV и защиту чужих FFmpeg с фильтром astats.
Процессы в этом тесте подменены; реальные процессы не завершаются.

Перед импортом учитывай: `shared.py` создаёт `.write_test` и папку логов в корне
исходников. Для проверок, которые не должны затрагивать рабочее состояние, копируй
Python-исходники и проверочные скрипты в отдельную папку без пользовательских
настроек/записей и запускай проверки там. `APP_DIR`, напечатанный `verify_project.py`,
должен указывать на эту копию. Один лишь другой cwd не изолирует импорт.

Ручная проверка: дважды сделать GIF и обрезку одной записи; прежний результат
должен остаться, новый — получить номер. Закрыть программу во время экспорта:
её процесс должен завершиться, старые файлы — сохраниться. Проверить обычную
запись с системным звуком, паузой и остановкой. Эти тесты не заменяют живую
проверку GUI, ddagrab/NVENC и устройств.

### Проверка DXGI-восстановления и короткого MP4

Из корня проекта:

```powershell
python verify_capture_recovery.py
python verify_capture_recovery.py --ffmpeg C:/ffmpeg/bin/ffmpeg.exe --nvenc
```

Путь FFmpeg заменяется на фактический; `--nvenc` требует NVIDIA. Тесты используют
только синтетические источники, не экран/микрофон. Они проверяют штатный stop с
живым аудио и без него, отсутствие оставшихся собственных процессов, сохранение
исходников, движение до разрыва, конечный stop-frame, новую сцену после склейки
и звук на обоих участках. Генератор сегментов обязан применять реальные
`append_segment_container_options`, включая MP4 timescale: иначе тестирует
несовместимые контейнеры, не рабочую запись. Артефакты сбоя теста остаются во
временной папке, путь печатается.

Ручной Windows-тест после перезапуска программы: записать 5 секунд движения,
нажать `Ctrl+Alt+Delete`, через 3–5 секунд вернуться, продолжить движение и
остановить спустя 1–2 секунды. Повторить без звука и с микрофоном/системным звуком,
а также с паузой после возврата. Проверить отсутствие 12-секундного зависания,
присутствие сцены до/после, стоп-кадр на недоступном интервале, длительность и
предупреждение. При FAIL прислать целую папку этой записи из `Логи проблем`;
временные MP4/WAV не удалять. Synthetic PASS не доказывает этот live-переход.

Изменяй `APP_BUILD`, когда меняется поведение записи, аудио, формат логов или пользовательская версия.

Изменяй `DIAGNOSTIC_SCHEMA`, когда меняется структура JSON/JSONL и старый анализатор может трактовать данные неверно.

Не повышай версию за чистое исправление текста документации.

## Требования к коммитам

Хорошие примеры:

```text
fix(audio): remove self reference from static method
fix(capture): preserve wall-clock duration at 72 fps
fix(logs): include worker traceback in session errors
refactor(ui): move webcam window without behavior changes
```

Один коммит должен иметь одну понятную причину.

## Регрессии сохранения v27

`python verify_save_safety.py --ffmpeg C:/ffmpeg/bin/ffmpeg.exe` проверяет восстановление с WAV, сохранность оригиналов, исключение производных копий, порядок двух сцен и звук во втором сегменте, отсутствующие/изменённые якоря, повреждённые исходники, trim раннего WAV и настоящий обрыв. Состояния автоостановки проверяются через завершение паузы/перезапуска и отмену устаревшего таймера. Используются только искусственные данные во временной папке.

Ручная проверка: установить небольшой лимит автоостановки и поставить запись на паузу либо вызвать восстановление захвата непосредственно перед истечением лимита. После завершения перехода запись должна сохраниться один раз. Затем сделать обычную запись со звуком, паузой и продолжением. Проверки состояний не подтверждают физические устройства, глобальные горячие клавиши, live GUI или EXE.

## Сохранение и переходы v28

`python verify_recording_publication.py` проверяет временный кандидат до проверки,
совпадение имён, отказ папки назначения, ошибку тайминга и отчёта, отложенный
«Стоп» во время запуска и лимит восстановлений после одного или редких кадров.
Это проверки состояний и файлов на искусственных данных, без захвата устройств.

`verify_save_safety.py` дополнительно проверяет обычное сохранение одного и двух
сегментов настоящим FFmpeg: все декодированные кадры и порядок сцен, наличие
звука, границы A/V, сохранность исходников и чужого файла при совпадении имени.

Ручная проверка после перезапуска: нажать «Стоп» из трея сразу при запуске записи;
затем записать 30–60 секунд движения со звуком, паузой и продолжением. Проверить
готовое видео и отсутствие оставшегося процесса записи. При ошибке сохранить
папку текущей записи из `Логи проблем`, временные сегменты и `.pending` кандидат.
