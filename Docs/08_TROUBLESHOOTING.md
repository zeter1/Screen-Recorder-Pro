# 08. Диагностика типовых проблем

## Ошибка при нажатии «Запись»

### Порядок

1. Открыть последний `diagnostic_latest.txt`.
2. Проверить `04_ошибки_и_трейсы.txt`, если папка записи успела создаться.
3. Найти полный traceback, а не только текст messagebox.
4. Определить этап: проверка звука, FFmpeg, backend, temp, логирование, UI.

### Пример уже найденной регрессии

```text
NameError: name 'self' is not defined
```

Причина: `@staticmethod` в аудиологике обращался к `self`. Такой класс ошибок ловит `verify_project.py`.

## Запись идёт рывками

Проверить:

1. `APP_BUILD` в `00`/`05`/`11`;
2. команду в `02`;
3. наличие `ddagrab=framerate=144` при 144→72;
4. фильтр wall-clock CFR;
5. `Non-monotonic DTS`, PTS/DTS и packet intervals;
6. `07` на stalls/speed/dup/drop;
7. `08` на CPU/GPU/NVENC/swap;
8. `09`/`10` на визуальные повторы;
9. классификацию motion pattern: continuous, bursty или stepwise;
10. техническую корреляцию кандидата с drop/stall/drift/swap/перегрузкой;
11. другой плеер и частоту монитора.

Не менять конвейер только из-за большого процента одинаковых кадров на статичной сцене.

## Видео ускорено или короче реального времени

Признаки:

- media duration меньше wall-clock;
- drift растёт с длительностью;
- `speed` стабильно около 0.97x при принудительных 72 FPS;
- схема `setpts=N*ticks`.

Исправление не должно возвращать битые PTS. Стабильная база использует wall-clock rebase + один fps-фильтр.

## `Non-monotonic DTS`

Проверить:

- не передаются ли сырые повторяющиеся PTS напрямую;
- не удалён ли нормализатор;
- не добавлен ли второй FPS-механизм;
- не изменён ли timescale;
- точную команду и контейнер.

Не лечить только игнорированием предупреждения.

## Нет системного звука

Проверить:

1. выбранное устройство в `05`;
2. поддерживает ли FFmpeg `wasapi`;
3. выбран ли системный output, а не Focusrite Analogue/microphone;
4. запустился ли Python CoreAudio loopback;
5. существует ли `.system_loopback.wav` и размер > WAV header;
6. события mix timing before/after;
7. файл `15_синхронизация_системного_звука.json` и применённый trim/delay;
8. есть ли аудиодорожка в финальном файле.

Если исходный CoreAudio WAV длиннее видео, это не надо скрывать одним `-shortest`.
Проверь `loopback_start_minus_video_start_seconds`: раннее начало должно быть обрезано,
позднее — задержано. Итоговые начало/конец дорожек после смешивания проверяются повторно.

Программа не должна молча сохранить успешный файл без обязательного системного звука.

Если в `04_ошибки_и_трейсы.txt` есть `0x88890004`, Windows сделал прежний audio endpoint недействительным. Текущая версия повторно открывает актуальный default output до 10 секунд. Если это не удалось, видео и доступная часть аудио сохраняются с явным предупреждением, а событие `python_loopback_incomplete` помечается как `ERROR`.

## Видео остановилось, но звук продолжался

Признаки:

- в `07_ffmpeg_progress_по_времени.jsonl` значение `frame` не меняется, хотя `out_time` растёт;
- в FFmpeg stderr есть `AcquireNextFrame failed: 887a0026` или `DXGI_ERROR_ACCESS_LOST`;
- аудиодорожка исходного сегмента заметно длиннее видеодорожки.

Частая причина — `Ctrl+Alt+Delete`: Windows переключает ввод на защищённый desktop
Winlogon, который обычная программа не имеет права захватывать. Текущая версия сразу
распознаёт DXGI-маркер в stderr, ждёт возврата `Default` desktop и продолжает запись
в новом сегменте. При финализации закрытая копия дополняется конечным стоп-кадром
до следующего сегмента или остановки. Записанный звук сохраняется; незаписанный
звук во время перезапуска источников восстановить нельзя. Подробности и границы
проверки — в `03_RECORDING_PIPELINE.md`.

Если нужен только Диспетчер задач без защищённого экрана, используй `Ctrl+Shift+Esc`.
Если автоматический перезапуск несколько раз подряд не дал здорового сегмента,
программа останавливает запись и сохраняет доступные сегменты с явным предупреждением.

Для длинного Python CoreAudio проверь `wav_validation`. Одного условия «файл больше
44 байт» недостаточно: размер тела обязан совпадать с RIFF-заголовком.

## Микрофон слышен только в одном канале

Проверить filter graph. Для микрофона должен быть mono → stereo pan:

```text
pan=stereo|c0=c0|c1=c0
```

## Звук уезжает после тишины

Вероятная причина: CoreAudio loopback записывал только активные пакеты и не заполнял тишину.

В текущем классе тишина рассчитывается по `perf_counter` и дописывается нулями. Не удалять эту логику.

## GUI «не отвечает»

Приоритетные причины:

- синхронный `process.wait/communicate/taskkill` в GUI-потоке;
- FFmpeg probe устройств из callback;
- `join()` без короткого timeout;
- Tkinter-вызов из фонового потока;
- DXcam create/start/stop/release;
- повторный start поверх незавершённого старта.

Проверить thread name, этап события и время между логами.

## После закрытия остаётся ffmpeg.exe

Проверить:

- процесс запущен ли через managed API;
- зарегистрирован ли в `child_processes`;
- вызван ли `terminate_process_tree`;
- не обошёл ли код `LifecycleMixin.exit_app()`;
- завершены ли аудиометры и webcam FFmpeg;
- есть ли diagnostic event subprocess finish.

## Файл повреждён или не открывается

Если в v25 оба закрытия занимали 12 секунд, затем происходил kill, а короткий
MP4 давал `moov atom not found`, причина подтверждена как бесконечный `tpad` в
живом фильтре. Исправление v26 — конечное восстановление после закрытия, не
увеличение timeout и не отключение проверки сегментов. Если MP4 содержит лишь
28 байт, в нём нет восстановимых видеокадров; другие MP4/WAV нужно сохранить.

Не удалять temp сразу.

Проверить:

- return code FFmpeg;
- trailer и stderr;
- `validate_media_file`;
- формат сегментов;
- concat compatibility;
- наличие видеопотока и длительности;
- quarantine incomplete output;
- свободное место и права.

## Папка программы перемещена и всё сломалось

Проверить использование `APP_DIR`, `get_program_entry_path()` и fallback data root. Не использовать абсолютные пути, сохранённые с компьютера разработчика.

## Логи говорят `ok`, но пользователь видит проблему

- проверить, что логи именно от текущей сборки;
- попросить точный timestamp субъективного рывка;
- сопоставить timestamp с `07`, `08`, `09`, `10`;
- проверить исходный контент и его FPS;
- проверить плеер;
- улучшить диагностику, не меняя стабильную запись без доказательств.
