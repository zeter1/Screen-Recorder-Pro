# 01. Обзор проекта

## Что делает программа

Screen Recorder Pro — Windows-программа для:

- записи всего экрана, отдельного монитора или выбранной области;
- аппаратного захвата через FFmpeg Desktop Duplication (`ddagrab`);
- кодирования NVIDIA NVENC или CPU x264/x265;
- записи микрофона и системного звука;
- паузы и продолжения через сегменты;
- плавающей панели и рисования поверх экрана;
- предпросмотра вебкамеры поверх окон;
- снимков области в буфер обмена;
- работы через системный трей и глобальные горячие клавиши;
- подробной диагностики плавности, времени, нагрузки и звука.

## Целевая среда

Основная среда:

```text
Windows 11
Python 3.12 x64
FFmpeg + FFprobe в PATH
NVIDIA GTX 1660 SUPER / NVENC
монитор 144 Гц
типичный выход 72 FPS
```

Программа имеет CPU/GDI fallback, но основной оптимизированный путь — `ddagrab + NVENC`.

## Текущая версия кода

В `screen_recorder/shared.py`:

```python
APP_BUILD = "2026-08-16-audio-sync-diagnostics-v21"
DIAGNOSTIC_SCHEMA = "screen_recorder_diagnostics_v17"
DXCAM_CAPTURE_ENABLED = False
```

Видеоконвейер этой версии сохраняет проверенную базу `ddagrab + wall-clock CFR + NVENC`.
Последняя запись перед улучшением A/V-якоря показала:

- ровный выходной FPS;
- отсутствие `Non-monotonic DTS`;
- отсутствие обратных PTS/DTS;
- минимальный drift между реальными часами и медиатаймлайном;
- отсутствие подтверждённой перегрузки CPU/GPU/NVENC;
- нормальную синхронизацию аудио и видео.

## Точки запуска

### Совместимый launcher

```text
Screen Recorder Pro.py
```

Он импортирует `main()` и нужен для привычного запуска, автозапуска и совместимости.

### Основная точка запуска

```text
main.py
```

Она:

1. создаёт `SingleInstanceGuard`;
2. запрещает вторую копию программы;
3. создаёт скрытый `Tk` root;
4. создаёт `ScreenRecorderProWin11`;
5. запускает `mainloop`;
6. при выходе завершает дочерние процессы и освобождает mutex.

## Где хранятся данные

Путь определяется через `screen_recorder/shared.py`.

Приоритет:

1. папка рядом с программой, если доступна для записи;
2. `%LOCALAPPDATA%/ScreenRecorderProWin11`;
3. домашняя папка пользователя;
4. временная папка.

Основные данные:

```text
settings/settings.json
settings/settings.backup.json
recording_temp/
Логи проблем/
```

Эти папки являются runtime-данными и не должны попадать в коммиты.

В `settings/settings.json` также сохраняются параметры собственных инструментов
скриншота: `screenshot_draw_color`, `screenshot_draw_size`,
`screenshot_arrow_color`, `screenshot_arrow_size` и глобальная позиция панели
`screenshot_toolbar_x/y`. При загрузке значения нормализуются, а координаты
ограничиваются текущим виртуальным рабочим столом.

## Основные зависимости

Из `requirements.txt`:

```text
psutil
numpy
Pillow
keyboard
pystray
dxcam
opencv-python
```

`dxcam` может быть установлен, но рабочий путь отключён константой `DXCAM_CAPTURE_ENABLED = False` из-за зависаний.

Внешние программы:

```text
ffmpeg.exe
ffprobe.exe
nvidia-smi.exe — желательно для расширенных логов GPU
```

## Основные принципы проекта

- Стабильность записи важнее архитектурной красоты.
- Ошибку нельзя маскировать «успешным» сохранением.
- Долгая операция не должна блокировать Tkinter.
- Все дочерние процессы должны быть управляемыми и завершаться при выходе.
- Логи должны позволять нейросети восстановить точную причину сбоя.
- Изменение поведения и структурный рефакторинг выполняются раздельно.
