# AGENTS.md — Screen Recorder Pro

## Назначение этого файла

Это проект Windows-программы для записи экрана на Python/Tkinter с FFmpeg, Desktop Duplication (`ddagrab`), NVIDIA NVENC, микрофоном, системным звуком, паузой, треем, плавающей панелью, скриншотами и подробной диагностикой плавности.

Работай как осторожный senior Python/Windows/FFmpeg-разработчик. Главная цель — улучшать проект без регрессий в уже плавно работающей записи.

Отвечай пользователю на русском языке простыми словами. Код, имена функций и технические решения должны быть профессиональными.

## Текущая стабильная база

Стабильная сборка на момент создания документации:

```text
APP_BUILD = 2026-07-18-ddagrab-wallclock-poll-v8
DIAGNOSTIC_SCHEMA = screen_recorder_smoothness_diagnostics_v8
```

Основной проверенный путь записи:

```text
Desktop Duplication / ddagrab
→ кадры D3D11 в GPU-памяти
→ временная шкала по реальным часам
→ единственный CFR-фильтр до целевого FPS
→ NVIDIA NVENC
→ контейнер MP4/MKV/AVI/MOV
```

Для монитора 144 Гц и выходных 72 FPS программа опрашивает `ddagrab` на 144 FPS и формирует файл на 72 FPS.

Стабильная цепочка видеофильтров для `ddagrab`:

```text
settb=expr=1/1000000,
setpts=RTCTIME-RTCSTART,
fps=<OUTPUT_FPS>:round=near,
settb=expr=1/39600,
setpts=PTS-STARTPTS
```

Выход использует:

```text
-fps_mode passthrough
```

## Критические инварианты записи

Не меняй перечисленное без доказательств из логов и отдельного теста:

1. Для `ddagrab + NVENC` нельзя добавлять `hwdownload`. Кадры должны оставаться в D3D11/GPU-памяти до NVENC.
2. Нельзя возвращать голую схему `setpts=N*ticks`. Она ранее сжимала временную шкалу и ускоряла длинную запись.
3. Нельзя одновременно использовать несколько CFR-механизмов: например, `fps`-фильтр плюс выходной `-r` или другой принудительный пересчёт кадров.
4. Для целевого FPS должен существовать ровно один осознанный механизм нормализации кадров.
5. `ddagrab` должен сохранять `dup_frames=1`, пока логи не докажут обратное.
6. Для 144 Гц / 72 FPS `get_ddagrab_poll_fps()` должен возвращать 144.
7. Не включай DXcam обратно: `DXCAM_CAPTURE_ENABLED = False`. В этом проекте DXcam вызывал тяжёлые зависания.
8. Не считай ровные PTS доказательством визуальной плавности. Проверяй также содержимое кадров, реальное время, `FFmpeg progress`, нагрузку и субъективный тест.
9. Не объявляй статичные участки подтверждёнными рывками без совпадения с техническими признаками.
10. Не меняй команды FFmpeg одновременно со структурным рефакторингом.

## Архитектурные правила

### Главный класс и mixin-структура

`ScreenRecorderProWin11` находится в `screen_recorder/app.py` и собирается из mixin-классов. Они используют общее состояние через `self`.

- Не добавляй `__init__` в mixin без явного согласования с `ScreenRecorderProWin11.__init__`.
- Не переставляй порядок mixin-классов без анализа MRO и совпадающих имён методов.
- Перед переносом метода найди все его вызовы и все поля `self.*`, которые он читает или меняет.
- Не создавай циклические импорты между mixin-модулями.
- Существующий `from ..shared import *` является частью текущей структуры. Не рефакторь все импорты одновременно с функциональной задачей.

### Tkinter и потоки

- Tkinter разрешено вызывать только из основного GUI-потока.
- Фоновый поток не должен обращаться к `StringVar`, `BooleanVar`, `winfo_*`, `update*`, `messagebox` или виджетам напрямую.
- Перед запуском фоновой операции скопируй значения Tkinter в обычные Python-поля.
- Результат фонового потока возвращай через `root.after(...)` или очередь.
- Долгие операции FFmpeg, ffprobe, анализ видео, завершение процессов и сборка файла не должны блокировать GUI.

### Дочерние процессы

Все процессы запускай через:

```python
self.start_managed_process(...)
self.run_managed_process(...)
```

Завершай через:

```python
self.terminate_process_tree(...)
```

Не используй новый голый `subprocess.Popen` без регистрации процесса. Иначе после закрытия могут остаться `ffmpeg.exe`, заблокированные файлы и зависшие папки.

Для операций с файлами, сетью и процессами предусматривай:

- тайм-аут;
- проверку кода возврата;
- сохранение stderr в диагностике;
- корректное закрытие ресурсов;
- понятную ошибку пользователю;
- сохранение доступной части записи при сбое, если это безопасно.

### Настройки

- Сохраняй обратную совместимость старого `settings.json`.
- Новая настройка должна иметь безопасное значение по умолчанию.
- Ошибка чтения одной настройки не должна ломать запуск.
- Сохраняй настройки атомарно и не затирай хорошую резервную копию повреждённым JSON.
- Не читай Tkinter-переменные из фонового потока.

### Аудио

- Обычный микрофон, `Line In` и `Focusrite Analogue 1+2` не являются системным звуком.
- При отсутствии FFmpeg WASAPI системный звук записывается через Python CoreAudio loopback в WAV и подмешивается после остановки сегмента.
- Нельзя молча сохранять «успешное» видео, если обязательный системный звук не записался или не подмешался.
- Микрофон приводится к mono, затем дублируется в stereo, чтобы голос не был только в одном канале.
- После изменений аудио обязательно проверяй начало, конец и длительность обеих дорожек через ffprobe.

### Диагностика

Логи — часть функционала, а не временный отладочный код.

- Ошибка должна попадать в `04_ошибки_и_трейсы.txt` с контекстом и traceback.
- Команда FFmpeg и значимый stderr должны попадать в `02_ffmpeg_команды_и_вывод.txt`.
- Важные этапы должны записываться структурированно в `01_события_записи.jsonl`.
- Не записывай бесконечные логи: соблюдай лимиты файлов и отсечение повторов.
- Не маскируй подтверждённую ошибку статусом `ok`.
- Не превращай обычную статичную сцену в подтверждённый «рывок» без корреляции с техническими данными.
- При изменении схемы логов обнови `DIAGNOSTIC_SCHEMA` и документацию.

## Ручная проверка на Windows после существенных изменений

1. Запустить `python "Screen Recorder Pro.py"`.
2. Убедиться, что появляется трей и плавающая кнопка.
3. Записать 30–60 секунд непрерывной прокрутки.
4. Проверить паузу и продолжение.
5. Проверить микрофон и системный звук.
6. Остановить запись и дождаться завершения сохранения.
7. Убедиться, что видео воспроизводится плавно, длительность реальная, звук не обрезан и не уехал.
8. Проверить, что созданы логи 00–13.
9. Проверить отсутствие `Non-monotonic DTS`, обратных PTS/DTS, серьёзного drift, зависания progress и перегрузки.
10. После полного выхода убедиться, что не осталось лишних `ffmpeg.exe`.

## Структурный рефакторинг

Структурный рефакторинг выполняй отдельно от изменения поведения.

- Один этап — один понятный набор переносов.
- Сначала перемести код без изменения тела функций.
- Сохрани публичные имена методов и точки вызова.
- После переноса сравни AST/поведение, импорт и число методов.
- Не удаляй совместимый launcher `Screen Recorder Pro.py`.
- Не объединяй mixin-файлы обратно в монолит без прямой просьбы пользователя.
